FlashQLA 在五档 GDN 测试中最快

CUDA Graph 下，相对 FLA 的加速比为 1.50–2.28×。8K 时三者分别为 FLA 576.23 μs、 FlashQLA 252.66 μs、FlashInfer 362.96 μs。

长序列下，与 cuDNN 的差距扩大

8K 时标准 causal SDPA 为 1,500.11 μs， 是 FlashQLA GDN 的 5.94 倍。 512 时则是 cuDNN 更快：28.01 vs 30.68 μs。两者计算语义不同。

短序列排序取决于计时方式

512 时，Eager 下 FlashInfer / FlashQLA 为 68.19 / 191.28 μs；Graph 下为 57.50 / 30.68 μs。两种方式的 L2 策略不同，差值不能全归因于 launch 开销。

比较边界：GDN 计入 Q/K L2 归一化与最终 recurrent state 输出； cuDNN Full 为标准 causal softmax attention，不输出 recurrent state。 输入与主输出形状相同，算法不等价；这些是 attention 算子入口的时间，未覆盖完整模型层。

测量口径与实现配置

共同输入 / 输出
Q,K,V,O∈R1×T×16×128\mathbf{Q},\mathbf{K},\mathbf{V},\mathbf{O}\in\mathbb{R}^{1\times T\times16\times128}

Q / K / V 为 BF16

GDN 计时范围

Q/K L2 norm→GDN prefill→最终 state 写出

初始 state 为零，最终 state 为 FP32。FlashInfer 在 API 外执行相同的 Q/K 归一化，并计入时间。

cuDNN causal Full Attention

O=softmax⁡ ⁣(QKT128+Mcausal)V\mathbf{O}=\operatorname{softmax}\!\left(\frac{\mathbf{Q}\mathbf{K}^{\mathsf{T}}}{\sqrt{128}}+\mathbf{M}_{\mathrm{causal}}\right)\mathbf{V}

公式按每个 head 计算，dropout=0。标准列只计 SDPA；“Full + Q/K norm”列另外计入 Q/K L2 归一化。

计时方法

Eager · 每次调用前清 L2

do_bench(warmup=25, rep=100)

用 CUDA events 计时，可能包含主机发射 kernel 的间隙。清 L2 操作在计时事件之外。

CUDA Graph · 不清 L2

do_bench_cudagraph(rep=20)
ti=treplay,iN,i=1,…,10t_i=\frac{t_{\mathrm{replay},i}}{N},\qquad i=1,\ldots,10

N 为每次 replay 展开的调用数。对 10 次 replay 的单次调用时间统计 median、p20 和 p80。

计时参数：warmup 和 rep 以 ms 为单位；quantiles=[0.5,0.2,0.8]。

运行条件：关闭梯度，seed=42；各实现分进程顺序测量，未锁 GPU 频率，未做跨进程重复统计。

计时外：输入生成、gate 激活预计算、首次编译 / autotune / plan setup，以及 projection、卷积、模型输出 norm/gate 和 backward。

实现细节与源码
  • cuDNN 强制使用 SDPBackend.CUDNN_ATTENTION。 BTHD → BHSD 通过 transpose view 完成，无 layout copy。
  • FlashInfer 的最终 state 按 V,K 存储；转为 K,V 只用于校验，不计时。 分派记录为 cp_delta_rule_dsl_sm120；metadata 中的 chunk_size=64 是脚本记录值。
  • 算子入口：bench.py（make_inputs / main）、 bench_flashinfer.py（prepare_call / main）、 bench_cudnn_attention.py（make_run / main）。 计时器实现见本环境 Triton 3.6.0 的 testing.py:60、testing.py:127。
