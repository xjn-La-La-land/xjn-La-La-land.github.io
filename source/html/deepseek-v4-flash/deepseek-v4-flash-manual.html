2.1 整体架构

DeepSeek-V4.1-Flash 是一个多模态混合专家（MoE）Transformer，接收图像和文本输入，并以自回归方式生成文本。语言 backbone 包含 40 个 causal Transformer 层，前 20 层构成 causal encoder，后 20 层构成 decoder。除最前面的两层只使用 Sliding-Window Attention（SWA）外，每一层都同时包含 global attention 和 SWA。

vision encoder 和 MLP projector 将图像转换为 visual embedding，与 text embedding 一起送入语言 backbone；多模态数据从语言模型预训练开始就参与训练。整体上，DeepSeek-V4.1-Flash 包含 552B backbone 参数和 196B Engram 参数，prefill 阶段每个 token 激活 8B 参数，decode 阶段激活 16B 参数。图 3 展示了完整架构。

Causal Encoder–Decoder（CED）和 Compressed Sparse Attention 2（CSA2）分别降低长上下文推理中不同部分的成本。CED 从 encoder 输出构建 decoder 的 global KV cache，使大部分 prompt token 可以跳过完整的 decoder 计算，同时保留各层自身的 SWA。这将 prefill 计算量降低近一半，减少了 Agent 上下文不断增长时处理新增输入或未缓存输入的成本。CSA2 则通过跨层共享 global KV 降低缓存存储开销，并复用稀疏选择结果来减少索引计算。在 decoder 中，Hierarchical Sparse Indexer 将后续 indexer 的搜索范围限制在较早 indexer 选出的候选池内，进一步减少每个 query 需要评分的 entry 数量。

我们保留了 DeepSeekMoE 的 shared expert 和细粒度 routed expert（Dai et al., 2024），并为 image token 与 text token 引入按模态区分的负载均衡（Wang et al., 2024a）。Single-Pass mHC（Xie et al., 2026）调整 residual stream 的混合方式，以支持更高效的 kernel fusion；Engram（Cheng et al., 2026b）引入稀疏访问的 conditional memory。backbone 预训练时不使用 MTP 模块，而是在 backbone 预训练结束后单独训练 DSpark（Cheng et al., 2026a），用于 speculative decoding。此外，我们将 main KV cache 压缩为 FP4，以进一步降低存储开销。以下各节介绍这些组件及相应优化。

2.1.1 多模态架构

多模态输入路径由 vision encoder 和 MLP projector 组成。对于每张输入图像，vision encoder 生成按空间网格排列的 visual feature。随后，3×33\times3 pixel-unshuffle 将每个局部邻域的特征重排到 channel 维度，降低空间分辨率；MLP projector 再将这些特征映射到语言 backbone 的 hidden dimension。最终得到的 visual embedding 被放入输入 embedding 序列中对应的 image-token 位置，与 text embedding 一起由语言 backbone 处理。

DeepSeek-ViT。 我们从头训练名为 DeepSeek-ViT 的 vision encoder，以原生支持不同分辨率的图像。该模型基于 Vision Transformer（Dosovitskiy et al., 2021），并做了以下修改。为支持任意分辨率输入，我们用 2D-RoPE 替代标准的 absolute positional embedding。为使 ViT 更贴近 LLM 的设计，我们将 patch embedding 层的卷积替换为 linear projection，以兼容 Muon optimizer；同时采用 RMSNorm（Zhang and Sennrich, 2019）和 SwiGLU（Shazeer, 2020），分别作为归一化方法和激活函数。在 visual feature 进入 LLM 之前，使用 3×33\times3 pixel-unshuffle 下采样，将 visual token 数量降至原来的 1/9，从而实际支持最高约 1344×13441344\times1344 像素的输入分辨率。

多模态 MoE 的 auxiliary-loss-free load balancing。 image token 和 text token 的表示分布不同，可能形成不同的 expert routing 偏好。仅平衡两种模态合计的负载，可能掩盖各模态内部的负载不均衡。因此，我们扩展了 auxiliary-loss-free load balancing（Wang et al., 2024a），为 text token 和 image token 分别维护一组 expert-wise correction bias。

routing 时，每个 token 使用所属模态的 correction bias 选择 expert，但仍使用原始 routing score 对选中 expert 的输出加权。每个训练 step 结束后，两组 bias 根据各自模态的 expert 负载独立更新。这样能够在每种模态内部平衡 expert 利用率，支持稳定、高效的多模态训练。

2.2 Causal Encoder–Decoder（CED）

Agent 工作流中的频繁 tool call 会产生大量 prefill 请求，KV cache 未命中时会带来显著的计算开销。为缓解这一瓶颈，我们受 YOCO（Sun et al., 2024）启发，提出 Causal Encoder–Decoder（CED）架构。YOCO 让上半部分网络直接共享下半部分网络生成的 KV cache，从而减少 prefill 计算。CED 在此基础上进行一系列结构改进，同时增强整体 KV cache 的表示容量和 KV 生成的计算深度。因此，在维持与 baseline 相当的模型表现时，CED 能将 prefill 计算量减少近一半。

对于 global attention，CED 将 Transformer 的前 L/2L/2 层视为 causal encoder。对于上半部分网络，即 l>L/2l>L/2 的 decoder 层，其 KV entry 不再由本层 hidden state HlH_l 生成，而是使用该层对应的 projection weight WlKVW_l^{KV} 和 WlZW_l^Z，直接从第 L/2L/2 层的 hidden state HL/2H_{L/2} 投影得到：

Cl=HL/2WlKV,Zl=HL/2WlZ,l>L2.C_l=H_{L/2}W_l^{KV},\qquad Z_l=H_{L/2}W_l^Z,\qquad l>\frac{L}{2}.
(1)

其中，CC 和 ZZ 分别表示 KV entry 及对应的 compression weight。这使 CED 能够在 prefill 阶段只计算前半部分网络，再以很小的额外计算开销获得上层的 global KV cache。

对于 SWA，CED 在全部层中保留传统的逐层计算。具体来说，任意第 ll 层的 local key 和 value 都直接由本层 hidden state HlH_l 生成，从而增加 local KV 生成的计算深度。但保留这种逐层计算方式也意味着需要 SWA replay。prefill 阶段，为生成 decoder 的 SWA KV cache，需要额外处理 nwin×L/2n_{\mathrm{win}}\times L/2 个 token，其中 nwinn_{\mathrm{win}} 是窗口大小。当多轮交互中每轮 prompt 都较短时，这部分 decoder 计算开销不容忽视。

已有研究（Chen et al., 2025）表明，SWA 的实际有效感受野远小于理论上的 nwin×L/2n_{\mathrm{win}}\times L/2。受此启发，我们引入 Decoder SWA Bounded Replay：只对 prompt 最后 nwinn_{\mathrm{win}} 个 token 执行 prefill，完成所需的 SWA 计算，从而显著降低开销。详细机制见 §3.2.2。

对于长度满足 N≫nwinN\gg n_{\mathrm{win}} 的序列，CED 将 prefill 复杂度从 𝒪(NL)\mathcal{O}(NL) 降低为：

𝒪(NL2+nwinL2)≈𝒪(NL2).\mathcal{O}\!\left(\frac{NL}{2}+n_{\mathrm{win}}\frac{L}{2}\right)\approx\mathcal{O}\!\left(\frac{NL}{2}\right).

因此，总体计算量约减半。

2.3 Compressed Sparse Attention 2（CSA2）

长上下文 serving 需要同时控制 KV cache 存储量和 attention 计算量。这些成本可以沿三个具有乘性关系的维度降低：

  • Entry 大小。 GQA（Ainslie et al., 2023）减少 KV head 数量；MLA（DeepSeek-AI, 2024）则在多个 head 之间共享较小的 latent。
  • 序列维度。 每 mm 个 token 压缩为一个 entry，例如 DeepSeek-V4 中的 CSA 和 HCA（DeepSeek-AI, 2026b）。
  • 层维度。 部分层复用其他层的 cache 和选择结果，不再各自维护；也可以将部分层替换为更高效的层。

已有工作验证了沿层维度压缩的有效性：IndexCache（Bai et al., 2026）跨层复用 Top-K 索引，降低 indexer 计算量；YOIO（Sun et al., 2026b）只计算一次 sparse routing，并在所有层间共享；HySparse（Gao et al., 2026）让 sparse 层复用 dense 层的 KV cache。不过，仅复用索引并不节省 main KV 存储；全网络共享 routing 会限制模型表现；混合设计仍保留 full attention 层。更重要的是，这些方法都没有同时覆盖上述三个维度。

CSA2 联合利用这三个维度：跨层共享 main KV 和 indexer K，允许不同层复用 Top-K 索引，同时将 cache sharing 与 index reuse 解耦。它还结合简化后的 compressor 和 Hierarchical Sparse Indexer，缩小 decoder 中后续索引层的搜索范围。

与 CSA 类似，CSA2 包含一个轻量 indexer，使用 indexer Q 和 indexer K 对 main KV entry 评分，为每个 query 选择 Top-K entry。每个 Q 同时关注这些选中的 entry 和本层的 SWA KV。CSA2 也支持压缩率为 1 的特例，即 main KV 不进行序列压缩。

CSA2 同时简化了 compressor 和 indexer。在 CSA 中，当压缩率为 mm 时，每个 main KV entry 由 2m2m 个原始 KV cache entry 生成，相邻压缩 entry 的输入范围存在重叠；压缩过程还使用 absolute positional embedding，编码这 2m2m 个 entry 的位置。CSA2 去掉了这种重叠和 absolute positional embedding。此外，CSA2 通过投影 main KV entry 得到 indexer K，替代了 CSA 从 hidden state 出发、单独执行压缩的路径。这两项设计都简化了实现，提高了训练效率。

以下 §2.3.1 和 §2.3.2 分别介绍跨层复用策略与 Hierarchical Sparse Indexer。

2.3.1 跨层 KV 与索引复用

每个 CSA2 层都被静态指定为 Full、Reindex 或 Reuse 三种模式之一。三种模式都会计算本层 query 和 SWA KV，再结合选中的 main KV entry 生成新的 attention output；区别在于如何获取 main KV、indexer K 和 Top-K 索引。图 4 展示了这三种模式。

Full 模式。 本层计算 main KV 和 indexer Q，从 main KV 投影得到 indexer K，再运行 indexer 产生新的 Top-K 索引。因此，它执行完整的 CSA2 计算路径，各组件职责与 DeepSeek-V4 中完整的 CSA 层相同。

Reindex 模式。 本层复用前面最近一层可用的 main KV 及对应的 indexer K。indexer 计算本层自己的 query，重新对复用的 key 评分，并产生新的 Top-K 索引。这允许不同层选择不同的稀疏 entry，同时保持 main KV 和 indexer K 共享。

Reuse 模式。 本层复用前面最近可用的 main KV，以及前面某个 Full 或 Reindex 模式层针对这份 main KV 计算出的最新 Top-K 索引。它直接使用该选择结果执行 attention，不再计算 indexer Q，也不再计算 index score。

共享 main KV 和 indexer K 可减少 cache 存储，复用 Top-K 索引则避免额外的 indexer 计算。Reindex 模式保留 cache sharing，同时允许各层改变所选 entry。当 CSA2 与 CED 结合时，decoder 中被指定为 Full 模式的层从第 L/2L/2 层，即 causal encoder 最后一层的 hidden state 计算 global KV。Reindex 和 Reuse 模式保持不变。

2.3.2 Hierarchical Sparse Indexer

跨层索引复用减少了 indexer 的执行次数，但剩余 indexer 仍需对因果关系允许访问的完整上下文评分。在极长上下文下，这部分开销仍是主要计算瓶颈。已有工作在 token-level indexing 之前，先对池化后的 block representation 评分并裁剪，以引入 indexer sparsity（Xu et al., 2026b）。

我们发现，在 decoder 中，可以直接使用较浅层 indexer 的信息，限制较深层 indexer 需要考虑的候选位置，而无需增加额外 state。因此，我们引入 Hierarchical Sparse Indexer，仅用于 CED 的 decoder，以减少 decode 时重复评分的开销。对每个 query，第一个 Full 模式层构建候选池，后续 Reindex 层将其作为搜索范围。候选池大小固定时，后续 indexer 的单 query 开销由随上下文长度线性增长变为常数。

该机制在 post-training 中引入，并在训练与推理时使用相同的候选范围约束，使较深层 indexer 在与推理一致的搜索范围内接受优化。图 5 展示了这一过程。

第一个 Full 模式层对所有因果可见的 main KV 位置评分，并为自身 attention 生成 Top-K 索引。同时，它以 block 为单位选择候选：取每个 block 内所有位置的最大 index score 作为该 block 的分数，再选出分数最高的 block。将这些 block 覆盖的位置汇集起来，就得到一个比最终 Top-K 集合更大的候选池。例如，选择 2,048 个 block、每个 block 包含 8 个位置，共得到 16,384 个候选位置。候选池决定后续 indexer 在哪里搜索，最终 Top-K 结果则决定每层实际读取哪些 main KV entry。

后续 Reindex 层仅对当前 query 对应候选池内的位置评分，并在池内选择本层 Top-K entry。Reuse 层不再执行新的索引计算，直接使用针对所复用 main KV 计算出的最新 Top-K 索引。因此，各索引层共享候选池，但最终选择结果可以不同。

复杂度边界。 候选池大小固定时，每个后续 indexer 为单个 query 评分的位置数量有固定上界，与上下文长度无关。第一个 Full 模式层仍需扫描完整的因果可见范围。因此，分层索引减少的是后续 indexer 的计算开销，初始的全范围扫描仍然保留。

2.4 高效架构扩展

2.4.1 Single-Pass mHC

我们在 DeepSeek-V4 中引入了 mHC（Xie et al., 2026），在相邻 Transformer block 之间维护 nn 路 residual stream。对每个 token，将这些 residual stream 记为 Xl∈ℝn×dX_l\in\mathbb{R}^{n\times d}，其中 ll 为 block 编号，dd 为 hidden dimension。其更新方式为：

Xl+1=BlXl+Clℱl(AlXl),(Al,Bl,Cl)=ℋ(Xl).X_{l+1}=B_lX_l+C_l\mathcal{F}_l(A_lX_l),\qquad (A_l,B_l,C_l)=\mathcal{H}(X_l).
(2)

其中，Al∈ℝ1×nA_l\in\mathbb{R}^{1\times n}、Cl∈ℝn×1C_l\in\mathbb{R}^{n\times1} 和 Bl∈ℝn×nB_l\in\mathbb{R}^{n\times n} 是根据 XlX_l 预测出的逐 token 系数。系数预测器 ℋ\mathcal{H} 包含 normalization 和 projection。

理想情况下，两个 block 之间的 residual 变换是从 (Xl−1,Yl−1)(X_{l-1},Y_{l-1}) 到 (Xl,X^l)(X_l,\hat{X}_l) 的一次映射，其中 X^l=AlXl\hat{X}_l=A_lX_l 是当前 block 的输入，Yl−1=ℱl−1(X^l−1)Y_{l-1}=\mathcal{F}_{l-1}(\hat{X}_{l-1}) 是前一个 block 的输出。这一映射需要读取 (n+1)d(n+1)d 个元素并写入 (n+1)d(n+1)d 个元素，因此 activation 访存量的下界为 (2n+2)d(2n+2)d。

实际的 DeepSeek-V4 使用 式 (2) 的 multi-pass 实现，由于数据依赖，以下三个 kernel 必须依次执行。

Residual update：沿 nn 维收缩。

Xl=Bl−1Xl−1+Cl−1Yl−1.X_l=B_{l-1}X_{l-1}+C_{l-1}Y_{l-1}.
(3)

系数计算：沿 ndnd 维收缩。

(Al,Bl,Cl)=ℋ(Xl).(A_l,B_l,C_l)=\mathcal{H}(X_l).
(4)

Input mixing：沿 nn 维收缩。

X^l=AlXl.\hat{X}_l=A_lX_l.
(5)

三个 kernel 分别读取 (n+1)d(n+1)d、ndnd 和 ndnd 个元素，合计写入 (n+1)d(n+1)d 个元素。再计入 ℱl\mathcal{F}_l 内的 pre-norm，总 activation 访存量为 (4n+4)d(4n+4)d，是理论下界的两倍。

在 ℋ\mathcal{H} 中，normalization weight 会离线合并到 projection weight 中，RMS 除法则在 projection 之后进行。因此，三个阶段中的两个可以共享同一次 residual 遍历：residual update 不需要沿 hidden dimension 做 reduction，所以计算出 XlX_l 的一个 tile 后，就可以立即用它累加 projection 输出，以及计算 RMS 所需的平方和。

Input mixing 无法融合到这次遍历中，因为必须完成所有 hidden tile 的 reduction 才能得到 AlA_l。因此还需要再次读取 XlX_l；第二次遍历可以同时完成 input pre-norm。这种 two-pass 实现的 activation 读写总量为 (3n+2)d(3n+2)d，比理论下界多读一次 XlX_l。

为此，我们提出 Single-Pass mHC，将 input-mixing 系数错开一个 block：每个 block 使用前一个 block 生成的 mixing coefficient，消除上述依赖：

Xl+1=BlXl+Clℱl(Al−1Xl),(Al,Bl,Cl)=ℋ(Xl).X_{l+1}=B_lX_l+C_l\mathcal{F}_l(A_{l-1}X_l),\qquad (A_l,B_l,C_l)=\mathcal{H}(X_l).
(6)

Input mixing 现在使用 Al−1A_{l-1}，而非 AlA_l，不再依赖由当前 XlX_l 计算出的系数。因此，每个 XlX_l tile 都可以立即同时用于 input mixing 和系数预测，无需等待完整 reduction。实验表明，这种偏移引起的模型表现下降可以忽略。

预训练阶段仍保留已有的 multi-kernel 实现，因为这一偏移仅改变每个 block 使用哪组 mixing coefficient。部署时，我们将 residual update、input mixing 和系数预测融合为一个 Mega-mHC kernel。该 kernel 实现原始 mHC 时的 activation 读写量为 (3n+2)d(3n+2)d，实现 Single-Pass mHC 时为 (2n+2)d(2n+2)d。

Mega-mHC 沿 hidden dimension 分 tile 处理 XlX_l。每个 tile 用于计算混合后的输入，并累加预测下一 block 系数 (Al,Bl,Cl)(A_l,B_l,C_l) 所需的量。该 kernel 还融合了 input pre-norm 和 FP8 转换。这样 residual 只需读一次、写一次，达到理想映射的 (n+1)d(n+1)d 次读和 (n+1)d(n+1)d 次写，将原始实现的 activation 访存量减半。

2.4.2 Engram

我们为 DeepSeek-V4.1-Flash 加入 Engram（Cheng et al., 2026c），即此前提出的 conditional memory 模块，用于将记忆与计算解耦。我们沿用原始 Engram 的 tokenizer compression、multi-head hashing、context-aware gating 和 multi-branch integration，并做了两项修改。第一，移除短 causal convolution，因为它带来的模型收益不足以抵消推理系统新增的复杂度。第二，使用 momentum update 后接 Sinkhorn balancing 的方式优化 Engram embedding，详见原报告 §2.5。

196B Engram 参数平均分配到两个模块。每个模块使用 NN-gram 阶数 {2,3,4}\{2,3,4\}，每个阶数包含 8 个 hash head，embedding 总维度为 2048。每个 head 索引一张约 16M entry 的表，各表大小选为互不相同的素数。embedding table 和 key/value projection 均采用 FP8 精度。

为平衡训练 pipeline stage 之间的内存占用，两个模块分别放置在第 1 层和第 14 层，层号从 0 开始。推理时，确定性寻址使系统能够通过后台 RDMA 从 host memory 预取 embedding，第一个模块的预取与第一个 Transformer block 的计算重叠。更多训练与推理实现细节见原报告 §3.1.3。

2.4.3 DSpark

DeepSeek-V4.1-Flash 使用 DSpark（Cheng et al., 2026a）进行 speculative decoding，结合半自回归 draft 生成和按置信度调度的 verification。

drafter 包含 3 个 Transformer block，sliding attention window 为 128 个 token。一次 forward 可并行计算 5 个 draft 位置的 base logits，同时由轻量的 Markov head 建模 draft token 之间的依赖。confidence head 预测各位置的条件接受概率，用于估计 draft 前缀被连续接受的概率。scheduler 将这些估计与 profiling 得到的推理引擎吞吐曲线结合，动态选择每个请求的 verification 长度，目标是在当前系统负载下最大化全系统的期望 token 吞吐。

DeepSeek-V3 的 MTP 模块（DeepSeek-AI, 2024）在整个预训练期间与 backbone 联合训练；DSpark 则在预训练结束后的专门阶段引入。在该阶段，backbone 保持冻结，只训练 DSpark。post-training 时，DSpark 继续随 backbone 一起训练，但 DSpark 目标产生的梯度不会传播到 backbone。这使 DSpark 能够跟随不断变化的 policy，既加速在线 serving，也加速 RL 和 OPD 的 rollout 生成。

2.4.4 FP4 Main KV Cache

长上下文 Agent 工作负载需要较大的单请求 KV cache，增加了 serving 成本。DeepSeek-V4 已对 FP4 indexer query 和 key 使用 quantization-aware training（QAT；Jacob et al., 2018），加速索引计算并缩小 indexer cache。尽管实验中的其他格式准确率更高，我们仍采用 OCP 标准的 MXFP4（Rouhani et al., 2023），以支持尽可能多的硬件平台。

现在，我们将 QAT 扩展到 main KV cache。这里使用 FP4 的目的是降低存储开销，而不是加速矩阵乘法。attention 计算前先对 cache value 反量化，就可以采用准确率更高的格式，而无需硬件原生支持该格式的矩阵乘法，从而保留跨平台兼容性。

在评估的约 4-bit 格式中，我们选择 E2M1，每 16 个 channel 使用一个 E4M3 scale。这一设计参考 NVFP4（Alvarez et al., 2025），但省略第二级 global scale，以兼顾准确率和实现简洁性。省略该 scale 后，main KV cache 仍有充足的动态范围：格式能表示的最大幅值为 448×6=2688448\times6=2688，远高于 cache 的幅值上界。

在 DeepSeek-V4.1-Flash 中，训练得到的 RMSNorm weight 最大幅值约为 1。经过 RMS normalization 后，512-channel KV latent 的 L2 norm 上界约为 512\sqrt{512}。RoPE 保持这一 norm，因此旋转后各 channel 的最大绝对值也不超过约 512≈22.6\sqrt{512}\approx22.6。此外，训练中观察到的最大幅值约为 10。因此，省略 global scale 没有带来可测量的准确率下降，并简化了 cache layout。

为支持 FP4 main KV cache，我们在 post-training 中引入 QAT。non-RoPE 和 RoPE 部分使用相同的量化格式。cache 在 RoPE 之后量化：在 RoPE 之前量化只带来很小的准确率改善，却会增加 decode 开销。由于 SWA KV cache 对量化较为敏感，我们仍对其使用 FP8。相比 DeepSeek-V4 的 FP8 main KV cache，这一格式将其在 HBM 中以及 offload 到 SSD 后的存储占用都降低近一半。

3.2 推理系统

DeepSeek-V4.1-Flash 将推理效率作为设计中的首要考虑。虽然架构在概念上较复杂，最终的 inference kernel 流程却很简洁。通过合理的 kernel fusion，我们将复杂操作封装在少量 fused kernel 中，并在 kernel 内充分流水化硬件资源的使用。这些 kernel 包括 FlashMLA（Li and Liu, 2025）中的 fused-RoPE-attention-RoPE-cast kernel，DeepGEMM（Zhao et al., 2025）中的 Mega-Gate、Mega-mHC 和 Mega-MoE，TileKernels（Wang et al., 2026a）中的 kernel，以及 DeepSelect（Qian et al., 2026）的 TopK kernel。

因此，绝大多数 Transformer 层，即 CSA2 使用 Reuse 模式的层，prefill 仅执行 15 个 kernel，decode 仅执行 11 个 kernel，实现高吞吐、低延迟推理。

部署层面采用 Encoder–Prefill–Decode（EPD）分离，使 vision encoding、prefill 和 decoding 能够独立扩展，并重叠执行。

3.2.1 Persistent KV Cache 管理

相同工作负载下，V4.1 的 persistent KV cache 占用降至 V4 的 1/8。这来自两个相乘的因素：persistent KV cache 不再保存 SWA KV，容量需求因此降低近一半；保留的 global KV 再通过架构和精度优化压缩到 V4 的 1/4。

在 V4 部署中，SWA KV 约占 persistent KV cache 容量的一半。global KV 和 SWA KV 分别管理，使用 LRU 淘汰策略。global KV 完整保存，命中时复用整个前缀。SWA KV 则只在两个位置保存：prompt 末尾和 output 末尾，以支持重新生成与多轮会话；命中后可从该位置恢复计算。

为保持较高命中率，我们在 SSD 上配置了足够大的 persistent KV cache，使典型工作负载下两类 KV 都能保留超过 72 小时。即使只在特定位置保留 nwinn_{\mathrm{win}} 个 KV entry，未经压缩的 SWA KV cache 仍带来显著存储开销，尤其是每轮较短的多轮会话。

持久化保存 SWA KV 成本高、效果也不理想，因为它的访问模式与 persistent KV cache 的长保留周期不匹配。global KV 的复用具有长尾特征；SWA KV 的复用却主要发生在活跃会话内分钟级的短窗口中，会话结束或进入下一轮后就不再使用。V4 技术报告提出 Zero SWA Caching，通过重新计算缺失的 SWA KV 避免存储开销。但精确恢复需要对 L×nwinL\times n_{\mathrm{win}} 个 token 执行完整 forward，在实际部署中代价过高。

因此，V4.1 调整了 persistent KV cache 的管理方式：

  1. 将 SWA KV 转入短期内存池。 SWA KV 不再放入 persistent KV cache，而是保存在由每台机器 10% host DRAM 构成的分布式内存池中。虽然总容量小得多，但其 TTL 只有几分钟，过期 entry 可以立即回收并用于新会话。在真实工作负载中，这种高周转率足以支持绝大多数并发活跃会话。global KV 仍保留在 persistent KV cache 中，保证至少 72 小时的生命周期。
  2. 通过 Encoder SWA Bounded Replay 处理未命中。 淘汰 SWA KV 必然导致部分 miss，但轻量恢复机制使其代价可控。对于不可避免但较少出现的“global KV 命中、SWA KV 未命中”请求，仅重新计算 nwinn_{\mathrm{win}} 个 token 就能恢复所需 state，无需对 L×nwinL\times n_{\mathrm{win}} 个 token 完整 forward。这个 bounded replay 机制是设计的基础：它将代价高昂的 miss 转为低成本的恢复过程，使系统能够从 persistent KV cache 中移除 SWA KV。详见 §3.2.2。

3.2.2 SWA Bounded Replay

SWA 的依赖会跨层累积，因此精确重建 LL 层的 SWA KV 需要重放 L×nwinL\times n_{\mathrm{win}} 个 token。SWA Bounded Replay 只重放最近的 nwinn_{\mathrm{win}} 个 token，并将 SWA 的访问范围截断到重放片段内，接受由此得到的近似 state。对于从位置 ss 开始的重放，位置 ii 的 query 只关注以下范围内的 SWA key：

[max(s,i−W+1),i].\left[\max(s,\;i-W+1),\;i\right].

Encoder SWA Bounded Replay。 这一机制使 prefix caching 仅依赖 global KV，从而可以从 persistent KV cache 中移除 SWA KV。

当 encoder SWA KV 缺失时，我们重放已缓存前缀最后 nwinn_{\mathrm{win}} 个 token，并与未缓存后缀一起处理。重放的 token 只重新生成 SWA KV；既有 global KV 直接复用，不重算也不覆盖。未缓存后缀则同时生成 global KV 和 SWA KV。

按此设计，重放所得前缀 state 是近似的，因此为未缓存后缀计算出的 global KV 和 SWA KV 会依赖 cache-hit 位置；在不同命中位置下，这些结果在数学上并不完全相同。实验表明，这种 bounded replay 策略对回复质量几乎没有影响。

Decoder SWA Bounded Replay。 这一机制将 decoder forward 的处理范围限制为 nwinn_{\mathrm{win}} 个 token，使整体 prefill 计算量降低近一半。

在 CED 中，decoder global KV 从 encoder 最终 hidden state 投影得到。阻止 prefill 在 encoder 处结束的唯一因素是 decoder SWA KV：它由各 decoder 层自身的 hidden state 生成，最初几个 decode step 需要使用它。由于我们不缓存 decoder SWA KV，精确重建需要对 prompt 最后 (L/2)×nwin(L/2)\times n_{\mathrm{win}} 个 token 执行 L/2L/2 层 decoder 计算。当较短的未缓存后缀接在较长的缓存前缀之后时，这项开销很大。

因此，我们也将 bounded replay 用于这一场景：每次 prefill 都重放 prompt 最后 nwinn_{\mathrm{win}} 个 token，将其 encoder 输出送入 decoder，并施加相同的 SWA 截断。生成的 decoder SWA KV 仅用于 decoding，不用于 prefix caching。

按此设计，重建出的 decoder SWA KV 与完整 decoder forward 得到的结果在数学上不等价。我们同样观察到，该策略对回复质量的影响可以忽略。为进一步提升稳健性，post-training 中也会模拟相同的 replay，让模型在训练时适应该行为。

4.2.1 模型配置

Transformer 共 40 层，hidden dimension d=5120d=5120。模型采用 CED 架构，encoder 和 decoder 各 20 层。最前面的两层只使用 SWA；encoder 剩余的 18 层使用压缩率 m=2m=2 的 CSA2，分为 3 组，每组 6 层且配置相同：首层使用 Full 模式，其余 5 层使用 Reuse 模式。

decoder 的 20 层使用压缩率 m=1m=1 的 CSA2，分为 5 组，每组 4 层。第一组的首层使用 Full 模式，其余 3 层使用 Reuse 模式。后续 4 组的配置相同：首层使用 Reindex 模式，其余 3 层使用 Reuse 模式。

所有 CSA2 层均设置 32 个 indexer query head，indexer head dimension 为 128，每个 query 为 sparse attention 选择 512 个 KV entry，即 attention Top-K 为 512。attention query head 数为 64，head dimension 为 512，query compression dimension 为 1280。Hierarchical Sparse Indexer 最多选择 2,048 个 block，每个 block 包含 8 个位置，总候选位置上限为 16,384。output projection 分为 8 组，每组中间 attention output 的维度为 1024。额外 SWA 分支的窗口大小 nwin=128n_{\mathrm{win}}=128。

所有 Transformer block 均使用 MoE 层，激活函数为 SwiGLU，采用阈值为 10 的 clamping（OpenAI, 2025）。每个 MoE 层包含 1 个 shared expert 和 384 个 routed expert，每个 expert 的 intermediate hidden dimension 为 2304；每个 token 激活其中 6 个 routed expert。mHC 的 expansion factor 为 4，Sinkhorn–Knopp 迭代次数为 20。

vision encoder 包含 32 层，hidden dimension 为 1024，attention head 数为 16，image patch size 为 14。vision MLP projector 包含 2 层，hidden dimension 为 5120。在上述配置下，DeepSeek-V4.1-Flash 包含 552B backbone 参数，prefill 阶段每个 token 激活 8B 参数，decode 阶段激活 16B 参数。
